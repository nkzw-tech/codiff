# GPT-6.1 walkthrough evaluation — 2026-11-15

Use GPT-6.1 Terra at medium reasoning as the production default and GPT-6.1 Sol at low
reasoning for default walkthroughs with at least 100 reviewable hunks and availability
fallback. GPT-5.5 remains an API baseline for this comparison, but it retired from Codex
with ChatGPT sign-in on October 14, 2026, so it cannot remain a product default.
See the [Codex retirement notice](https://learn.chatgpt.com/docs/models?surface=cli#gpt-55-retirement).

The predefined model menu now includes GPT-6.1 Terra, GPT-6.1 Sol, GPT-6 Luna, and GPT-6 Astra.
Terra uses medium reasoning when no effort is explicitly configured; the other predefined
choices use low. Both Terra 6.1 and Sol 6.1 are available in Codex on paid ChatGPT plans,
subject to account and workspace access. See [plan availability](https://learn.chatgpt.com/docs/pricing#feature-availability).

## Method

- Evaluated all four fixed cases twice per configuration: the previous production defaults,
  GPT-6.1 Terra at low and medium effort, GPT-6.1 Sol at low, GPT-6 Luna at low, and GPT-6 Astra
  at low. The baseline uses GPT-5.6 Terra below 100 hunks and GPT-5.5 at or above 100 hunks.
- All 48 generations succeeded through the production Codex app-server transport, with no
  model fallbacks. Every normalized walkthrough had complete total hunk coverage and no
  unknown hunk IDs. Normalization assigns omitted hunks to support; total coverage does not
  mean that the main review path explains every important behavior.
- Used Codex CLI 0.167.1 and Codiff revision `3b061bc49121cb8cf95273d6cc66d41535c2068e`.
  Walkthrough prompts, case fixtures, and scoring rubrics were unchanged. All inference ran
  through the configured local harness-proxy, with its dedicated Astra route enabled.
- Judged each output in a separate `evals/judge.mjs` turn with GPT-6 Astra at high reasoning,
  inspecting the commit with read-only git commands. All 48 judgments completed successfully,
  and each total equals its component scores. The same judge was used for every candidate,
  including Astra itself; these are model judgments, not independent human ratings.
- Scores below are the average of two judgments. Times are the median of two generations,
  including transport and normalization. Runs overlapped, and the additional Terra medium
  run overlapped with judging. Shared host and service load limit timing precision.
- This is a small suite of four commits. Treat differences as evidence for this workload,
  not general rankings of the models or statistically conclusive results.

## Decision

- **Default:** Select GPT-6.1 Terra at medium reasoning. It has the highest aggregate score,
  86.1, and improves medium-case quality by 9 points over the previous defaults. Accept the
  latency cost: 19.8s versus 10.1s for the medium case, and 11.5s versus 7.4s for the focused
  case. Low effort remains an explicit speed option, but loses 9.5 points on the focused case,
  including the successful-copy feedback contract, and reduces its main-path coverage from
  72% to 44%.
- **Large walkthroughs and fallback:** Replace GPT-5.5 with GPT-6.1 Sol at low reasoning.
  This retains the stronger-model role for large changes and follows the documented paid-plan
  replacement for GPT-5.5. Sol scores 70 versus 67.5 on the large case, at 31.2s versus 21.4s.
  Terra medium also scores 70 and is faster there (24.6s); the fixed suite does not establish
  a large-case quality advantage for Sol over Terra. Sol's 88.5 on the medium case is the
  strongest result on that case. Keep the existing 100-hunk routing threshold without tuning
  a new size policy to these four commits.
- **Availability:** Retry an unavailable model with Terra and then Sol, skipping duplicates.
  Sol can therefore fall back to Terra too. No automatic fallback selects GPT-5.5 or GPT-5.6.
  Explicit reasoning overrides remain intact, including on fallback. Existing saved model
  selections remain configurable; an unavailable GPT-5.5 selection recovers through the new
  fallback chain, and the app saves the successful replacement. Users with an available old
  model can select Terra 6.1 and clear the effort override to adopt the new defaults.
- **Cache:** Include the resolved Codex reasoning effort in walkthrough cache keys, so Terra's
  previous automatic low-effort results are not reused after its default changes to medium.
- **Shared weakness:** Every configuration still underexplains some large-review interactions.
  The baseline itself misses important tests and includes a factual error in one medium
  attempt. A future prompt or coverage improvement should be evaluated separately; no prompt
  changes were mixed into this model comparison.

All candidates pass the existing aggregate 10% quality gate. That gate averages cases and
therefore does not rule out the focused-case regression. `compare.mjs --enforce` passes fully
for Luna and Astra, but fails the repository-state timing gate for Terra low (95.0ms),
Terra medium (173.4ms), and Sol (103.6ms), against an 87.7ms baseline with a 4.4ms allowance.
Repository loading code did not change, and these measurements overlapped other work, so
contention is a plausible explanation rather than an established model effect. The failed
gates remain recorded; this evaluation does not claim a clean performance-gate pass for
those candidates.

## Catalog audit

Discovery uses the installed CLI's visible catalog for its configured account and provider,
retaining the existing hidden-entry and malformed-entry checks. Codiff does not maintain a
model denylist or treat informational retirement timestamps as access decisions. Unavailable
models are handled by the fallback chain, and custom model IDs remain configurable.

GPT-5.5 remains available through API authentication, which explains why the local proxy could
evaluate it despite its ChatGPT retirement. API catalog presence does not establish ChatGPT
subscription access. The predefined choices and automatic fallbacks use current models;
runtime discovery can still show legacy models when the installed CLI advertises them.

## Reproduction and artifacts

Run labels under the ignored `evals/runs/` directory:

- `gpt61-baseline-20261115`
- `gpt61-terra-low-20261115`
- `gpt61-terra-medium-20261115`
- `gpt61-sol-low-20261115`
- `gpt61-luna-low-20261115`
- `gpt61-astra-low-20261115`

Each directory contains prompts, raw responses, normalized walkthroughs, generation metadata,
judge outputs and events, and generated reports. Reproduce with the same model and effort:

```sh
node evals/run.mjs <production-label> --production-defaults --repetitions 2
node evals/run.mjs <candidate-label> --model gpt-6.1-terra --effort low --repetitions 2
node evals/judge.mjs <label>
node evals/report.mjs <label>
node evals/compare.mjs gpt61-baseline-20261115 <candidate-label> --enforce
```

The judge command inherits the configured Codex model and effort; match Astra/high for this
comparison. The earlier [2026-09-24 evaluation](gpt6-2026-09-24.md) is historical context;
its scores are not the baseline for this run.

The saved baseline used the previous defaults. Reproducing it requires the pre-migration
revision with `--production-defaults --effort low`; the current production command selects
Terra/medium below 100 hunks and Sol/low at or above 100. The runner now supports automatic
effort and records `actualEffort` so it does not silently force one effort across both roles.

An additional `gpt61-production-smoke-20261115` run used the new production defaults once per
case. All four generations succeeded without fallback: Terra/medium on small, focused-small,
and medium (6.7s, 9.7s, 15.4s), and Sol/low on large (29.8s). This verifies production model
and effort routing; these four outputs were not judged or added to the quality comparison.
